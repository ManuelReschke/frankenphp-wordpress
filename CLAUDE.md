## Project Overview

This is a FrankenPHP + WordPress Docker boilerplate project that provides a complete WordPress development environment using FrankenPHP (a high-performance PHP application server built on Caddy), MariaDB, and phpMyAdmin.

## Common Commands

### Environment Setup
```bash
# Initialize development environment
make init-dev

# Initialize production environment  
make init-prod

# Download and install WordPress
make install-wp

# Fix WordPress file permissions
make fix-perms
```

### Development Workflow
```bash
# Start the stack (build if needed)
make up

# Start existing containers
make start

# Stop containers (keep data)
make stop

# Stop and remove containers
make down

# Restart containers
make restart

# View container logs
make logs

# Rebuild images
make build

# Full cleanup (removes everything)
make clean
```

### WordPress Configuration
```bash
# Set FS_METHOD to 'direct' in wp-config.php
make set-fs-direct
```

## Architecture

### Docker Services
- **frankenphp**: Custom PHP 8.5 container with FrankenPHP 1.13.0 and the Cloudflare DNS module
  - Dev: ports 8080:80, 8443:443, plain HTTP via `caddy/Caddyfile.dev`
  - Prod: port 443:443, TLS via Cloudflare DNS-01 (`CLOUDFLARE_API_TOKEN`)
  - Includes PHP extensions: bcmath, exif, gd, intl, mysqli, zip, opcache, redis
  - Process user is `HOST_UID:HOST_GID` from `.env` (no recursive chown on every start)
- **db**: MariaDB 12 database server (port 3306)
- **dragonfly**: Dragonfly Redis-compatible cache server (port 6379)
- **phpmyadmin**: Database management interface (port 8081)

### File Structure
- `Dockerfile`: Custom FrankenPHP image with WordPress-required PHP extensions
- `docker-compose.dev.yml`: Development configuration with HTTP ports. Mounts `../wp-plugin-traffictradexy`.
- `docker-compose.prod.yml`: Production configuration with HTTPS only. Same plugin mount.
- `docker-compose.yml`: Generated by `make init-dev` or `make init-prod` and gitignored.
- `caddy/`: Caddy web server configuration
  - `Caddyfile`: Production global config, including Cloudflare DNS-01
  - `wordpress.caddyfile`: WordPress site block and security headers
  - `Caddyfile.dev` and `wordpress.dev.caddyfile`: Local HTTP on `:80` without ACME
- `entrypoint.sh`: Starts as root, then drops to `HOST_UID:HOST_GID` and launches FrankenPHP
- `wordpress/`: WordPress source code (created by `make install-wp`)

### Environment Variables
Configure in `.env` file:
- `SERVER_NAME`: Site address (dev default: `http://localhost`)
- `HOST_UID` / `HOST_GID`: User the container runs as (match `id -u` / `id -g`)
- `CLOUDFLARE_API_TOKEN`: DNS-01 token for production certificates
- `MYSQL_DATABASE`: Database name (default: franken)
- `MYSQL_USER`: Database user (default: frankenuser)
- `MYSQL_PASSWORD`: Database password (default: frankenpass)
- `MYSQL_ROOT_PASSWORD`: Database root password (default: rootpass)
- `REDIS_HOST`: Redis server hostname (default: dragonfly)
- `REDIS_PORT`: Redis server port (default: 6379)

### Build Process
1. `make init-dev` or `make init-prod` copies the appropriate compose file
2. `make install-wp` downloads WordPress from German localized source
3. `make up` builds the custom FrankenPHP image and starts all services
4. The container runs as `HOST_UID:HOST_GID`. Use `make fix-perms` only when ownership has drifted.

### Key Features
- FrankenPHP provides high-performance PHP execution with built-in Caddy web server
- Dragonfly Redis-compatible cache server for WordPress object caching
- Automatic SSL certificate generation in production (via Caddy)
- Security headers configured in wordpress.caddyfile
- Asset caching for static files (CSS, JS, images)
- Health checks for all services
- Persistent database and cache storage via Docker volumes

### Redis/Dragonfly Configuration
- Dragonfly container configured with 512MB memory limit
- Redis PHP extension installed and available
- Environment variables `REDIS_HOST` and `REDIS_PORT` available in FrankenPHP container
- Compatible with WordPress Redis plugins (e.g., Redis Object Cache, WP Redis)
- No authentication required by default (suitable for development)
